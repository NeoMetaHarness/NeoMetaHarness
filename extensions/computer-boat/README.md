# Boat computer provider

Enable `computer-boat` in Neo extensions, then configure its **Boat API base URL** and **Boat API key** in Settings. The key uses the kernel's `secret: true` settings property and is stored in the encrypted vault. The default URL is `https://boat.dev/api/v1`. All Boat requests use `@neometaharness/egress`, which requires HTTPS, checks DNS at socket lookup to deny private, loopback, link-local and metadata addresses, refuses redirects, limits response bodies to 1 MB, and supplies a default 30-second timeout. For a self-hosted PandaOS Boat API on a LAN, an administrator may enable `allowPrivateNetwork` in Settings (off by default), using a trusted HTTPS certificate. The isolated test suite injects a fake HTTP transport without configuring HTTP or loopback as the API URL.

Call `computers.provision` with `providerId: 'computer-boat'` and optional `spec.type` (`small`, `default`, `large`, `xlarge`) and `spec.ttlSeconds`. Every created sandbox is labeled with its Neo computer ID and workspace ID. To fork a running, Neo-managed computer within the same workspace, pass its Neo computer ID as `spec.forkOf`. Provision and fork use Boat's `Idempotency-Key` header. `computers.release` stops the sandbox and retains its newest disk snapshot. `computers.terminate` permanently deletes it. Admins and owners may call `POST /x/computer-boat/snapshot` with `{ "id": "neo-..." }` to create a named saved snapshot of a computer in their workspace. This matches the role required for provision and release.

Actions and captures travel through the shared ComputerRegistry, which handles per-bot capability tokens, human lease priority, kill-switch preemption, origin/key safety policy, and action audit. The provider uses Boat's remote command endpoint to run X11 `xdotool` input and ImageMagick's `import` screen capture inside the sandbox. The sandbox environment must provide `python3`, `xdotool`, `import` and a working X11 desktop. Captures reject invalid or truncated PNG data. `screen()` requires the trusted workspace, holder type and exact lease principal ID (user ID or agent ID) before retrieving Boat's bearer WebRTC URL. A lease without a principal ID cannot disclose a URL. The current shared registry only passes the holder type, so a future authenticated viewer integration must forward the principal from registry state to `lease()` and `screen()`, never from request data. No Gateway route exposes or logs this URL. Boat's documented desktop response has no expiry field, so the underlying URL's lifetime is uncontrolled. Only obtain it for an actively authorized viewer and discard it after use.

API sources checked on 2026-11-20: `https://docs.boat.dev/api/v1`, `/api/reference/sandboxes/create-sandbox`, `/api/reference/sandboxes/fork-sandbox`, `/api/reference/sandboxes/stop-and-archive-sandbox`, `/api/reference/sandboxes/permanently-delete-sandbox-data`, `/api/reference/agent/execute-sandbox-command`, `/api/reference/agent/get-desktop-streaming-url`, `/api/reference/snapshots/get-latest-sandbox-snapshot`, `/api/reference/snapshots/save-saved-snapshot` (all under `https://docs.boat.dev`). Live cloud and PandaOS compatibility require operator validation. `pnpm test:p3-11` uses an isolated fake Boat HTTP server and makes no billable calls.

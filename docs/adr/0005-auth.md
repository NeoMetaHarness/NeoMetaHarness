# ADR 0005 · Auth and teams: Better Auth on Kysely, Neo enforces engine access

Status: **Accepted** · 2026-11-18 · Evidence: [P0-5 auth draft](../../spikes/P0-5-auth-draft/ADR-auth.md) (Antigravity; Better Auth proof reproduced by the PM twice from a clean copy, 10/10 PASS)

## Context
[docs/02 §4](../02-architecture.md#4-the-neo-gateway): workspace → members → roles (owner, admin, member, viewer) → scoped resources. Local accounts in v1, OIDC/SSO later. It must be zero-setup for single-user desktop and real multi-user for a VPS team. Neo also holds the credentials **into** each engine, and those engines enforce little or no per-user access themselves.

## Options
| | **Better Auth 1.7.25** | Hand-rolled (Lucia-style) | OIDC-first (openid-client) |
|---|---|---|---|
| Local accounts, sessions | built in | ~150 LOC we own | needs a local IdP |
| Workspaces, invites, roles | `organization()` plugin, custom roles via `createAccessControl` | our tables + middleware | external |
| API tokens for CLI/remote | `@better-auth/api-key` (separate package) | our token table | custom |
| Passkeys, OIDC later | plugins | hand-written ceremonies | native |
| DB | Kysely adapter (ADR 0003) | any | n/a |

Both the hand-rolled baseline and Better Auth passed the same 10 checks: signup, login, workspace, invite viewer, viewer write → **403 via Better Auth org permissions**, owner write, viewer read, token issue, token write, revoked token → 401.

## Decision
**Better Auth `1.7.25`** (exact pin) with `@better-auth/kysely-adapter`, `organization()` (owner/admin/member + a custom `viewer` role via `createAccessControl`, merged with the default roles) and `bearer()` for App/CLI sessions. **API tokens use `@better-auth/api-key@1.7.25`** (hashed, scoped, expiring keys), not repurposed sessions. The spike's session-as-token workaround is not carried forward.

- **Desktop zero-setup:** on first start in desktop mode the gateway creates the local owner and workspace and gives the shell a loopback-only session. Small Neo code, tested.
- **node:sqlite:** Kysely's SQLite dialect needs a 15-line bridge (`reader = stmt.columns().length > 0`) because `StatementSync` has no `.reader`. It lives in `@neometaharness/db`, with a test.
- **Engines:** Neo is the access boundary. It maps roles to engine credentials per the [engine credential map](../../spikes/P0-5-auth-draft/ADR-auth.md#engine-credential-map): T3 scoped sessions (17 scopes; viewer gets `orchestration:read`), Hermes dashboard token + per-profile `API_SERVER_KEY` (all-or-nothing upstream, so Neo enforces roles before forwarding), DSH via the process boundary + vault-projected env. Engine credentials live in the vault (P1-3), and the vault's `authorizeVault` hook is backed by these roles.

## Consequences
- P1 auth task: wire Better Auth into the gateway (oRPC context → user, workspace, role). Back `authorizeVault` and every `/x/<engine>/` route with role checks. Prove the API-key plugin (issue, scope, expire, revoke) and desktop bootstrap. The same 10 checks run in `neo check`.
- Pin exactly. Better Auth upgrades re-run the auth suite.
- OIDC/SSO and passkeys are plugin additions later, with no schema rewrite.
